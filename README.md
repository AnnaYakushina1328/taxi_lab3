# Домашнее задание 03: Проектирование и оптимизация реляционной базы данных

## Вариант 16 — Система заказа такси

---

## Описание

В рамках лабораторной работы спроектирована реляционная база данных PostgreSQL для системы заказа такси.

Реализованы:

- схема базы данных для основных сущностей предметной области;
- ограничения целостности;
- тестовые данные;
- индексы для часто используемых запросов;
- SQL-запросы для всех операций варианта;
- анализ оптимизации запросов;
- запуск PostgreSQL через Docker Compose.

> В данной версии репозитория представлена именно БД-часть лабораторной работы: схема, тестовые данные, SQL-запросы, оптимизация и Docker-запуск PostgreSQL.

---

## Сущности системы

В базе данных реализованы следующие сущности:

- `users` — пассажиры;
- `drivers` — водители;
- `orders` — заказы / поездки;
- `payments` — платежи;
- `reviews` — отзывы.

## Схема базы данных

### Таблицы

| Таблица | Назначение | Количество тестовых записей |
|--------|------------|-----------------------------|
| `users` | Пользователи-пассажиры | 10 |
| `drivers` | Водители с данными автомобиля | 10 |
| `orders` | Заказы и поездки | 10 |
| `payments` | Платежи | 7 |
| `reviews` | Отзывы | 5 |

### Логические связи

- один пользователь может создать много заказов;
- один водитель может выполнить много заказов;
- один заказ может иметь один платёж;
- один завершённый заказ может иметь один отзыв.

---

## Основные ограничения

В схеме базы данных используются:

- `PRIMARY KEY` для всех таблиц;
- `FOREIGN KEY` для связей между сущностями;
- `UNIQUE` для логинов, номеров машин и других уникальных полей;
- `CHECK` для контроля допустимых значений статусов, рейтингов, координат и цен;
- `NOT NULL` для обязательных полей.

---

## Индексы

В проекте добавлены индексы для ускорения типовых операций:

- `idx_users_login` — поиск пользователя по логину;
- `idx_users_full_name` — поиск пользователя по имени;
- `idx_drivers_status` — выборка доступных водителей;
- `idx_drivers_location` — поиск водителей по координатам;
- `idx_orders_passenger_id` — история поездок пассажира;
- `idx_orders_status` — выборка активных заказов;
- `idx_payments_order_id` — поиск платежа по заказу.

Подробный разбор приведён в файле `optimization.md`.

## Быстрый старт

### Запуск PostgreSQL через Docker Compose

```bash
docker compose up -d
```

### Проверка статуса контейнеров

```bash
docker compose ps
```

### Просмотр логов PostgreSQL

```bash
docker compose logs -f postgres
```

### Подключение к базе через psql

```bash
docker exec -it taxi-postgres psql -U taxi -d taxi
```

### Подключение локально через psql

```bash
psql -h localhost -U taxi -d taxi
```

```sql

FROM users
WHERE login = 'passenger1';
```

```sql

FROM active_orders;
```

```sql
SELECT o.id, o.status, o.pickup_address, o.destination_address
FROM orders o
WHERE o.passenger_id = 1
  AND o.status IN ('created', 'searching', 'accepted', 'in_progress');
```
